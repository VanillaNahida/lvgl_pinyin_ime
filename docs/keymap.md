# 键位与布局规范

本文档是 `lvgl_pinyin_ime` 组件的键位与布局唯一权威说明。UI 代码（`src/ui/ime_keymaps.c`）
中的键位表必须与本文档逐项一致。

宽度单位 `width_u`：**十分之一单位**（10 = 1u），含义随该行的对齐模式而变 ——
这一条是本文档的核心，旧实现"同样的 10 单位在不同页面代表不同尺寸"的混乱就是从这里来的：

| 对齐模式 | `width_u` 的含义 | 行的宽度 | 用在 |
| --- | --- | --- | --- |
| `IME_ROW_ALIGN_CENTER` | **标准键宽 U 的十分之一**（9 = 0.9u） | 按键宽之和 + 间距，**整行居中** | 26 键 R1–R3、九键 R1–R3 |
| `IME_ROW_ALIGN_FILL` | 只是**本行内的相对权重** | 铺满网格宽度（扣除间距后按权重分） | 所有底部功能行、符号页 |
| `IME_ROW_ALIGN_GRID` | 预留（按显式逻辑列坐标） | 尚未实现，求解器会明确拒绝 | — |

`U` 由键盘的**参考行**（`ime_keyboard_t::ref_row`）反算：
`U = (网格宽度 - (参考行键数-1) × 间距) / (参考行权重之和 / 10)`。
26 键的参考行是 R1（12 个键、权重和 120 → 12u），九键与符号页各自的参考行见键位表。

> 因为 `CENTER` 行按同一个 `U` 计算、再整行居中，各行权重之和**可以不同**
> （26 键 R1/R2/R3 分别是 120/111/114，加起来分别是 12u/11.1u/11.4u），
> 第二、三行因此天然缩进 —— 这正是标准手机键盘的画法。
> 反过来，`FILL` 行只看行内比例，权重之和是多少都不影响外观。

`FILL` 行的分配用**最大余数法**：先各取整数部分，剩下的像素发给小数部分最大的键。
于是 20/20/30/25/25 会得到 51/51/76/63/63 这样的结果 ——
等权重的键一定等宽，而且整行（含间距）一个像素都不剩。

`CENTER` 行的取整用**边缘吸附**：每个键的左右边缘换算成像素 `px(u) = round(u × U / 10)`
（u 是该边缘距离行首的十分之一单位数），键宽 = 右边缘 - 左边缘。这样同时成立三件事：

- **参考行一个像素不剩地铺满网格**，最外侧的 `符` / `⌫` / `?123` / `✓` 直接顶到控件
  左右边缘，两侧没有背景色窄条（控件 root 的左右内边距也是 0，见
  `IME_STYLE_ROOT_PAD_X`）；
- **同一个单位位置上的键宽度严格相同**：26 键 R1 的 `q` 与 R2 的 `a` 都在 1.5u 处，
  九键四行的第 k 列都在同一位置 —— 所以列在不同行之间是对齐的；
- 行宽天然不会超过网格，不需要"先四舍五入、放不下再全体向下取整"这种全局开关。

代价只有一个：同一行里**相邻的、逻辑宽度相同**的键可能差 1 px（21/22 交替）。
那是"精确铺满"的必然结果，并排的键差 1 px 看不出来，远好过整条边空着。

> 全文档禁止使用 emoji。`⌨` `⇧` `⌫` `⏎` `✓` 等以 Unicode 几何符号或内联 SVG 实现。

> 本文档描述**完整的布局规范**，包含尚未实现的模式。与双拼、模糊音相关的条目
> （例如「`分词` 在双拼模式下自动隐藏」）目前只有规范、没有实现：双拼与模糊音属
> 「规划中」，见 [README 的功能与现状](../README_zh-cn.md#功能与现状)。当前实际可用的
> 是中文/英文两种语言模式与 26 键/九键两种键盘。

```
├──────────────────────────────────────────────────────────────┤
```

### 1.1 按键行为表

| 键 | 位置 | 行为 |
| --- | --- | --- |
| `符` | R1C1 | 打开数字/常用符号混合面板（P1） |
| `q`–`p` | R1C2–R1C11 | 输入字母（键面按语言/大写状态显示大小写，见 1.4） |
| `⌫` | R1C12 | 有拼音缓冲 → 删拼音；缓冲空 → 删文本框字符；**按住连删**（每 100 ms 一个）；按住时出现「← 左滑清空输入框」提示，**手指左滑到提示条左端即清空输入框**（含未上屏拼音）——见 1.5 |
| `⇧` | R2C1 | **英文**：单击 = 下一个字母大写（一次性）、再单击 = 大写锁定、第三次 = 取消；大写生效期间键面高亮（蓝底白字）。**中文**：字母一律大写、此键**无效**（不改变状态）。长按：切换中/英（两种模式下都可用） |
| `a`–`l` | R2C2–R2C10 | 输入字母（键面按语言/大写状态显示大小写，见 1.4） |
| `⏎` | R2C11–R2C12（2u） | 换行（单行 textarea 下无效） |
| `分词` | R3C1 | 在全拼缓冲末尾插入 `'`；英文模式置灰；双拼模式自动隐藏 |
| `-` `.` `,` `:` | R3C2 / R3C10–R3C12 | 中文模式输出全角 `－` `。` `，` `：`；英文模式输出半角 |
| `z`–`m` | R3C3–R3C9 | 输入字母 |
| `?123` | R4C1–R4C2（2u，行内权重 20） | 打开 P1，与 `符` 等效 |
| `⌨` | R4C3–R4C4（2u，行内权重 20） | 在九键 ↔ 26 键之间切换（开了语音时是 26 → 9 → 语音页 三页循环） |
| `（CN）空格` | R4C5–R4C7 附近（行内权重 30） | 输出空格；有拼音缓冲时上屏当前候选 |
| `中/英` | 行内权重 25 | 显示当前语言（中 / 英），点击切换 |
| `✓` | R4 末位（行内权重 25） | 有拼音缓冲 → 上屏当前选中候选；无缓冲 → 收起键盘并发 `LV_EVENT_READY` |

> R4 是 `FILL` 行，权重是**行内比例**：20 + 20 + 30 + 25 + 25 = 120 恰好等于 12u，
> 于是这一行的左右边界和上面几行对齐。旧实现里"语音开"的那一版是 20/20/30/15/15 = 100，
> 少了整整 2u，空格与右侧两个键都被压窄 —— 语音早就改成独立的一页了，那两套数值没有
> 任何理由不同，现已合并成一套（见 `src/ui/ime_keymaps.c` 的 `s_k26_r4` 注释）。
| `[<]` `[>]` | 候选栏两端（各 1u） | 候选词上一页 / 下一页；到达边界时置灰。图标优先用 LVGL 自带的左右箭头（`LV_SYMBOL_LEFT/RIGHT`，FontAwesome 私用区 U+F053/F054）；字体里没有这两个字形时退回 Unicode 箭头 ← →（见 `pager_caption()`，自带字体的字符集里只有后者） |

**按下反馈**：所有能点的东西（字母/功能键、候选词、九键区拼音 chip、翻页箭头）在按下时
都换一层更深的底色。样式上靠 `s_key_pressed`，它有两点容易踩：

- **必须自己写 `bg_opa`**。样式只携带它定义的属性，候选词的底色来自 `s_cand_btn`
  （`bg_opa = TRANSP`）—— 按下样式只改 `bg_color` 的话，等于给全透明背景换颜色，
  候选词看着就是"按了没反应"。
- **加样式的顺序 = 优先级**，所以顺序是 基础 → `s_key_active`(CHECKED)
  → `s_key_pressed`(PRESSED) → `s_key_disabled`(DISABLED)。按下态必须排在选中态
  **之后**，否则大写锁定键按下去还显示锁定的蓝色，看不到按下反馈。

### 1.2 拼音浮窗

- 位置：**候选栏上方**（候选栏上沿之上 + 小偏移），也就是控件内容区**之外**
- 只在有拼音缓冲时显示，缓冲为空就隐藏 —— **不预留任何空间**（不会有空带）
- 样式：半透明底 + 圆角 chip，显示当前拼音缓冲（含 `'`）
- 九键模式不显示它 —— 那边拼音在"选拼音"行里，两个都显示就是同一句话印两遍

实现上有三件事必须一起成立，缺一个就会出问题：

1. **浮窗是 `LV_OBJ_FLAG_FLOATING`**。flex 布局与 `calc_content_height()` 都会跳过
   floating 子对象，所以它既不占候选栏宽度、也不影响控件高度 —— 这正是"不用预留
   空间"的做法。
   ⚠ **别改成 `IGNORE_LAYOUT`**：那只让它不参与布局，**仍然**算进父对象的内容高度；
   把浮动子对象摆在 `LV_SIZE_CONTENT` 父对象的内容区外面，就是"父对象多高取决于
   子对象、子对象位置又取决于父对象"的自反馈，而
   `lv_obj_update_layout()` 的 `while(scr->scr_layout_inv)` 没有次数上限 —— 真机上
   表现是 LVGL 任务一直重排、看门狗超时（PC 落在 `calc_content_height`）。
2. **位置用静态对齐**（`lv_obj_align(TOP_LEFT, x, -(芯片高+1))`），不用
   `lv_obj_align_to(候选栏, ...)`：后者会记住 base 并在 base 移动时重新对齐，而候选栏
   的位置由父对象布局决定，同样会形成上面那种环。内容区第一行就是候选栏，所以
   "候选栏上方"就等于内容区 `y = -(芯片高 + 1)`。
3. **控件和它的每一层祖先都要允许溢出**（`ime_ui_chip_prepare()`）：LVGL 把子对象裁在
   父对象盒子里，除非父对象带 `LV_OBJ_FLAG_OVERFLOW_VISIBLE`，而那时的可用区域是
   "盒子 + `ext_draw_size`" —— 所以还得在 `LV_EVENT_REFR_EXT_DRAW_SIZE` 里把扩展
   绘制区撑到浮窗那么高。少一层都会被那一层裁掉，而 App 里包键盘的容器往往正好是
   `LV_SIZE_CONTENT` 紧贴键盘（最容易咬到）。

> 宿主渲染测试里 `host_ui_render ... chip` 会把这三条都断言一遍（浮窗出现 / 控件高度
> 不变 / 浮窗画在控件上方 / FLOATING / 祖先允许溢出）。

### 1.3 候选栏

- 结构：`[‹]`（1u，LVGL 左右箭头图标） + 候选词区（flex 自适应） + `[›]`（1u）
- **一屏放几个是量出来的**（`cand_measure()`）：候选长度差得很远 —— 拼音短的时候是
  一堆单字（20 px），打长了会出"中华人民共和国"（140 px）。UI 按实际字宽逐个量，
  放不下就停，再 `ime_session_set_page_size(n)` 告诉会话，**翻页步长也用它**
  （所以翻页不会跳过没显示过的候选）。上限仍是 `CONFIG_LV_PINYIN_IME_CAND_PAGE_SIZE`
- **每个候选的宽度也要显式给**（`lv_obj_set_width(btn, LV_PCT(pct))`），两层原因：
  - 候选按钮原来靠 `flex_grow` 平分，而 flex 的"基准宽度"取子对象**当前**宽度 ——
    刚换过文字的按钮基准还是旧值，140 px 的长词和 20 px 的单字会被摊成一样宽，
    长词按钮装不下自己的文字，标签就溢到邻居上（用户报的"候选字在显示范围外"）。
    所以 `flex_grow` 从候选样式里搬到了单独的 `s_cand_grow`，只有九键拼音 chip 用
  - 给的是**百分比**不是像素：候选行宽度要等布局跑完才准（翻页键、控件宽度都可能
    刚变过），按"量的时候那个宽度"算像素，最后几个候选会差出十几像素、探出右边界。
    百分比在布局时按真实宽度换算
  - ⚠ 百分比**取整之后还要按像素复核**：各项之和 ≤ 100% 并不等于放得下 —— 每个百分比
    各自向下取整丢掉的零头不占地方，但候选按钮**之间**的 `pad_column`（2 px）是实打实
    的。复核不通过就把最宽的那一项削 1%，直到真的放得下。九键打满一屏（8 个候选）时
    最后一个候选被切掉半个字就是这个账没算对（`cand_pct_to_px()` 照着 LVGL 的取整方式
    算，复核才有意义）
  - ⚠ `lv_obj_set_width()` 必须**在 `ime_style_apply_candidate()` 之后**调用：
    本工程用的 LVGL 9 里它就是一条本地样式，而那个函数开头的
    `lv_obj_remove_style_all()` 会把它一起清掉
- 剩余宽度平分给每个候选，所以不论一页几个都铺满整行（右侧不留空）
- 候选区本身不滚动，翻页由两端箭头负责（到边界置灰）

> 候选栏的宽度不在布局引擎（`ime_layout.c`）的管理范围内：它的宽度由**文字量**决定，
> 而键盘的键宽由网格决定。两者共用的是行高（`IME_UI_ROW_HEIGHT_PX`）与控件边距。

### 1.4 字母大小写

字母在键表里只有小写一份，键面大小写由 `key_label()` 按当前状态算出来：

| 语言 | 大小写 | 说明 |
| --- | --- | --- |
| 中文 | **恒为大写** | 拼音键盘的习惯画法；`⇧` 在这边不改变任何状态 |
| 英文 | 大写 = `shift != OFF` | 一次性 / 锁定都算；否则小写 |

大小写状态由 **session 持有**（`ime_session_shift()`），UI 只负责显示，提交的字符
由 `ime_session_push_letter()` 决定——两者不可能对不上。一次性大写由
`push_letter()` 在**用完的那个字母上**把它自己归位成 `OFF`（只清
`one_shot_shift` 会让键盘看起来"锁定解不掉"）。切换中/英时 shift 归零：中文下
这个状态既看不见也关不掉，留着会在切回英文时突然生效。

### 1.5 `⌫` 按住连删 + 左滑清空

按住 `⌫` 会走 LVGL 的 `LV_EVENT_LONG_PRESSED_REPEAT`（默认每 100 ms 一次），
每次走的是**和单击同一条路径**（先删拼音、缓冲空了删文本框字符）：

- 长按到达时（`LV_EVENT_LONG_PRESSED`）在键盘右上角（正好在 `⌫` 上方）弹出提示条
  「← 左滑清空输入框」，并记下"要滑多远"= 提示条宽度（夹在 72~240 px）；
- 按住期间手指左滑到该距离（`LV_EVENT_PRESSING`）→ 清空输入框并收起提示条，
  这一轮按住不再重复触发；
- 松手（`LV_EVENT_RELEASED` / `PRESS_LOST`）→ 收起提示条。

两个 LVGL 细节决定了实现方式：

1. `⌫` 上加了 `LV_OBJ_FLAG_PRESS_LOCK`。按住期间 LVGL 会不断按手指位置重新命中
   对象（`lv_indev.c` 的 `pointer_search_obj`），不锁的话手指一滑出这个键，
   `PRESSING` 就断了、还会收到 `PRESS_LOST`；
2. 松手时 LVGL **无条件**补发一个 `CLICKED`（只跳过 short click），所以长按过的那
   一次松手要把这个 `CLICKED` 吃掉，否则会多删一个字符。

## 2. 面板体系（共 4 个面板）

```
P0 主键盘 ──[ 符 / ?123 ]──►  P1 数字 + 常用符号混合面板
                                 │
                                 ├─[ 左下角 ABC ]──► 返回 P0
                                 ├─[ 123 ]─────────► P2 纯数字面板 ─[ABC]─► P0
                                 └─[ 更多 ]────────► P3 全部符号列表面板 ─[ABC]─► P0
```

### 2.1 P1：数字 + 常用符号混合面板（10u 宽）

```
┌────────────────────────────────────────────────┐
│  1   2   3   4   5   6   7   8   9   0         │  R1  10×1u
├────────────────────────────────────────────────┤
│  @   #   ￥   %   &   *   -   +   (   )        │  R2  10×1u
├────────────────────────────────────────────────┤
│      更多           其他符号          ⌫        │  R3  4u + 4u + 2u
├────────────────────────────────────────────────┤
│  ABC        123         空格          ✓        │  R4  2u + 2u + 4u + 2u
└────────────────────────────────────────────────┘
```

| 键 | 行为 |
| --- | --- |
| `0`–`9` | 直接输入数字 |
| `@ # ￥ % & * - + ( )` | 直接输入对应字符 |
| `更多` | 打开 P3 全部符号列表面板 |
| `其他符号` | 在当前面板内切换到另一批常用符号：`~ ! ? / \ | [ ] { } < >` |
| `⌫` | 删除 |
| `ABC`（左下角） | 返回 P0 主键盘 |
| `123` | 打开 P2 纯数字面板 |
| `空格` / `✓` | 输出空格 / 上屏 |

### 2.3 P3：全部符号列表面板

```
┌──────────────────────────────────────────────────────┐
│  [常用] [标点] [数学] [单位] [箭头]  ← 分类页签         │
├──────────────────────────────────────────────────────┤
│  ~ ! ? / \ | [ ] { } < >                             │
│  … — 、 。 ， ； ： ？！ 《》 〈〉 【】 〔〕               │
│  ± × ÷ ° ′ ″ Ω μ § ¥ € £ $                           │
│  ← → ↑ ↓ ⇒ ⇔ ∞ ≈ ≠ ≤ ≥ √                             │
```

## 3. 九键布局（T9）

```
┌───────────────────────────────────────────────────────────┐
│  ┌────┐                                                   │  ← 拼音浮窗
│  │ 94 │                                                   │
│  └────┘                                                   │
├───────────────────────────────────────────────────────────┤
│ 候选拼音行：  xi   yi   zi   …              （横向可滑动）    │  ← 高亮当前项
│                ▲ 高亮（主题色底 + 反色字）                    │     点击可切换
├───────────────────────────────────────────────────────────┤
│ 候选词行： [<]  西   洗   系   细   析   希   息   稀  [>]   │  ← `<` `>` 翻页
├───────────────────────────────────────────────────────────┤
│   123     ,。?!    ABC     DEF      ⌫                     │  R1  CENTER  12u
│  2.4      2.4      2.4     2.4      2.4                    │
├───────────────────────────────────────────────────────────┤
│   中       GHI     JKL     MNO      分隔                   │  R2  CENTER  12u
├───────────────────────────────────────────────────────────┤
│   拼音     PQRS    TUV    WXYZ       ✓                    │  R3  CENTER  12u
├───────────────────────────────────────────────────────────┤
│  选拼音      ⌨              空格                          │  R4  FILL    12u
│   20         20              60        （= 100 权重）      │
└───────────────────────────────────────────────────────────┘
```

> 九键四行都是五个键、每键 2.4u（`CENTER` 行，`ref_row` = R1），所以四行彼此完全对齐、
> 数字列等宽；底部一行是 `FILL`（20/20/60）。
>
> ⚠ 早期版本这里还有一个 `#if CONFIG_LV_PINYIN_IME_VOICE_ENABLE && CONFIG_LV_PINYIN_IME_VOICE_KEY_K9`
> 分支，把空格从 72 缩到 48（24+24+48 = 96，比别的行少 2.4u）。两个问题：那个 Kconfig
> 选项**根本不存在**（死代码），而且那一行里并没有 `IME_KEY_VOICE` —— 缩窄空格并不会
> 变出语音键。九键的语音入口和 26 键一样是 `⌨` 键切到语音页，所以现在只有一个数值。

| 键 | 行为 |
| --- | --- |
| `ABC` / `DEF` / `GHI` / `JKL` / `MNO` / `PQRS` / `TUV` / `WXYZ` | 追加数字 2–9 到九键缓冲；随后 `ime_t9_gen()` 刷新候选拼音行与候选词行 |
| 候选拼音行点击 | 选中该拼音串为当前拼音 → 刷新候选词行；高亮该按钮 |
| 候选词行 `[<]` `[>]` | 候选词翻页（每页 `CONFIG_LV_PINYIN_IME_CAND_PAGE_SIZE` 个），边界置灰 |
| `123` | 打开 P1 数字/常用符号面板（与 `,。?!` 打开的是同一个面板，见 2.1） |
| `,。?!` | 同上（历史上是"标点批次"，两个键落到同一个 P1 面板） |
| `⌫` | 删数字缓冲；缓冲空 → 删文本框字符 |
| `中` | 切换中/英（键面显示当前语言） |
| `拼音` | 切回中文拼音九键 |
| `分隔` | 插入 `'`（等同 26 键的"分词"） |
| `✓` | 上屏 |
| `⌨` | 切换 26 键 / 九键（开了语音时含语音页） |
| `选拼音` | 展开 / 收起候选拼音行（默认展开） |
| 底部 `空格` | 输出空格；有拼音缓冲时上屏当前候选 |

⚠ 候选拼音行**只在真有拼音串可显示时才占位**（`ime_ui_refresh_t9()` 里按
`九键 && 选拼音 && count > 0` 决定显隐）：它是一行透明容器，空着就是键盘中间
一条和背景同色的空带（看着像"布局坏了"）。显隐切换会改行数，所以那里顺带调一次
`ime_ui_apply_sizes()`，让总高度仍然等于 `IME_FIT_HEIGHT`；判断这一行是否参与分摊时
**直接看 HIDDEN 标志**（而不是再看一次 `mode` 与 `t9_row_visible`），免得两处条件各写
一遍、越走越不一致。语音页则完全不走这套分摊：它没有"键行"，高度由三个区段自己分
（见 [voice.md](./voice.md) §3）。

## 4. 英文模式

- 复用 26 键键盘，R1/R2/R3 行为同英文全键盘
- `分词` 置灰；`. , : -` 输出半角
- `中/英` 与 `（CN）空格` 键面显示 "英文模式"

### 5.1 改了键位之后怎么验

| 想验的东西 | 命令 |
| --- | --- |
| 键表是否自洽、几何是否满足规范（不需要 LVGL 库，秒级） | `build/host_layout_test/host_layout_test` |
| 真控件的位置与尺寸、多种分辨率、某个面板 | `build/host_ui_render/host_ui_render out.ppm <k26\|k9\|p1\|p1alt\|p2\|p3\|en> - layout [宽x高] [目标高度]` |
| 语音页 | 同上，但要用 `-DIME_HOST_VOICE=ON` 配出来的构建，mode 用 `voice` |
| 真机 | 调 `lv_pinyin_ime_dump()`：它会打印 layout 与 layout check 两行（行高、标准键宽、网格宽度、越界/重叠/间距/居中的计数） |

`host_layout_test` 会遍历**每一张键表 × 七种屏幕宽度 × 五种键盘区高度**，断言
"同一逻辑宽度的键在任何行都是同一个像素宽度""填充行一个像素都不剩""居中行两侧留白相等"
"不越界不重叠"——这些以前只能在真机上一张一张看。
